# Deploy ForgeFlow on Render

> Historical document. Deployment and capability statements below describe their recorded date and are not the current capability overview. See [current capabilities](en/current-capabilities.md) and the [judge guide](en/judge-guide.md).

**Historical runbook.** The Render review service is suspended. The current
public product uses the [Linux VPS deployment](en/deployment.md) and
[isolated judge workspaces](../deploy/vps/REVIEWERS.md). The source repository is
now public. The configuration and read-only restrictions below describe the
former review deployment, not the current executable demo.

This is the runbook for a hosted, read-only ForgeFlow review instance: one
Render web service built from `deploy/Dockerfile.api`, serving the React
workbench and the curated `demo-runs/` subset. The service has no model key and
no ERP credential, and it cannot start new experiment runs.

The Blueprint lives in [`render.yaml`](../render.yaml). All steps below are
performed in the Render Dashboard and your DNS provider; no Render API calls are
needed.

## 1. Prerequisites

- **Private GitHub repository:** `KevinXia69/ForgeFlow`.
- **Render GitHub App access:** in Render, open **Account Settings → GitHub →
  Configure account** and grant the Render GitHub App access to this repository.
  A private repository that is not on the GitHub App's repository list will not
  appear in the Blueprint or Web Service picker.
- **A generated invite code** (at least 16 characters). Generate one locally:
  ```bash
  python -c "import secrets; print(secrets.token_urlsafe(24))"
  ```
  Keep it out of the repository; you will paste it into Render's environment
  variable prompt.
- **A generated `demo-runs/` tree committed to the deploy branch:**
  ```bash
  uv run python scripts/build_demo_runs.py
  ```
  The builder copies only the allowlisted manifest, summary, attestation,
  Harbor result/reward and recovery-plan files (no agent traces) and writes
  `demo-runs/README.md`. Commit the generated tree. The image bakes it in at
  `/app/demo-runs`; if it is missing, `/api/runs` returns an empty list.
- **The web build inputs:** `deploy/Dockerfile.api` is a multi-stage build that
  compiles `web/` with Node and copies the result into the Python image. Keep
  `dockerContext: .` so both `web/` and `demo-runs/` are in the build context.
- **Region:** Singapore is fixed at service creation and cannot be changed
  later. Moving regions requires creating a new service.

## 2. Create a new service (do not reuse WayRaft)

> Create a **new service**. Do not repurpose or rename the old WayRaft service
> at `wayraft.onrender.com`, and do not make it the deployment target.

1. In the Render Dashboard choose **New + → Blueprint** (recommended, because
   this repository already has `render.yaml`).
2. Connect GitHub if prompted, grant the GitHub App access to
   `KevinXia69/ForgeFlow`, and select that repository and the `main` branch.
3. Render reads `render.yaml` and proposes one web service named `forgeflow`
   with the Docker runtime, `./deploy/Dockerfile.api`, context `.`, health check
   `/api/health`, plan `starter`, region `singapore`, and automatic deploys off.
4. When prompted for `FORGEFLOW_INVITE_CODES` (the `sync: false` variable),
   paste the generated invite code. `FORGEFLOW_SESSION_SECRET` is generated by
   Render; do not paste a secret into the repository.
5. Apply/create the service and wait for the first deploy to reach **Live**.
   The health check must pass before Render routes traffic.

If you create it as a plain **New + → Web Service** instead of a Blueprint, use
these exact settings:

| Setting | Value |
| --- | --- |
| Name | `forgeflow` |
| Language / runtime | `Docker` |
| Branch | `main` |
| Dockerfile path | `./deploy/Dockerfile.api` |
| Docker context | `.` (repository root) |
| Docker command | `sh -c "forgeflow api --host 0.0.0.0 --port $PORT"` |
| Health check path | `/api/health` |
| Instance type / plan | `starter` |
| Region | `singapore` |
| Auto deploy | `off` |

The Docker command is required because Render replaces the image's `CMD`. The
Dockerfile deliberately has no `ENTRYPOINT`, so the command above becomes the
whole process command and binds to Render's assigned `$PORT`.

## 3. Exact environment variables

| Key | Value | Why |
| --- | --- | --- |
| `FORGEFLOW_DEPLOYMENT` | `review` | Marks the instance as the review deployment (`/api/config`); validated by the API settings. |
| `FORGEFLOW_DATA_ROOT` | `/app/demo-runs` | The curated, baked-in run subset. The app reads it and never writes there. |
| `FORGEFLOW_PUBLIC_RUNS` | `p5-B-nop-meta-r1,p5-heldout-2281-pi-r1,permission-split-pi-20261021-09,permission-split-pi-b-20261021-01` | Makes these four curated runs visible to signed-in reviewers. Other unowned runs remain hidden. |
| `FORGEFLOW_APPROVALS_ROOT` | `/tmp/approvals` | Approval records go to ephemeral local storage, not to a Render disk or the ERP. |
| `FORGEFLOW_KNOWLEDGE_ROOT` | `/app` | The image copies `README.md`, `docs/`, and `contracts/` to `/app` for cited knowledge answers. |
| `FORGEFLOW_SECURE_COOKIE` | `true` | The session cookie is `Secure` and only travels over HTTPS. Render provides TLS. |
| `FORGEFLOW_RUNNER_ENABLED` | `false` | Disables run creation; this is the write switch for the review instance. |
| `FORGEFLOW_SESSION_SECRET` | Render `generateValue` | 256-bit random session-signing secret; never stored in git. |
| `FORGEFLOW_INVITE_CODES` | `sync: false` (enter manually) | Reviewers exchange an invite code for a session; no code is committed. |

Do not add `NEBIUS_API_KEY`, `OPENAI_API_KEY`, Odoo credentials, or any ERP
write credential. Nothing in this image reads them, and their absence is part
of the read-only guarantee.

Keep the public run list explicit when updating the demo bundle. An omitted
list hides all unowned recorded runs; `*` would expose every unowned run found
under the data root, including any later additions.

### Why review mode does not write

- `FORGEFLOW_RUNNER_ENABLED=false` disables `RunService`: `POST /api/runs`
  returns `503 {"detail":"runner_disabled"}`, no CLI process is spawned, and no
  model or ERP call can be made. With the runner disabled there is no code path
  from the web service to a recorded or live ERP write.
- `FORGEFLOW_DEPLOYMENT=review` is the deployment label exposed by
  `/api/config`; it does not grant any capability. It is paired with the runner
  switch above so the deployed configuration is explicit and testable.
- The image contains no model key and no ERP credential, and it does not mount
  `/etc/odoo`. Reading recorded runs and issuing approval records are the only
  operations available.
- Approvals are still writable under `/tmp/approvals`. They are review records,
  not ERP writes, and they are **ephemeral**: a Render deploy, restart, or
  instance replacement discards them. Do not treat them as durable audit
  storage.
- `FORGEFLOW_SECURE_COOKIE=true` requires HTTPS. Use the Render URL or the
  custom domain below; do not test with plain HTTP.

## 4. Custom domain and TLS

`forgeflow.onrender.com` may already be taken globally. If Render rejects the
name, choose another service name (for example `forgeflow-review`); the
`onrender.com` hostname is not a stable contract. A custom domain is the stable
answer.

1. In the new service open **Settings → Custom Domains → Add Custom Domain**
   and enter a hostname you control, for example `review.example.com`.
2. Render displays the DNS target for that domain. At your DNS provider create
   a **CNAME** record:
   - Host/name: `review` (or the subdomain you chose)
   - Value/target: exactly the hostname Render displays
3. Wait for Render to verify the record. TLS is automatic: Render provisions
   and renews the managed certificate after DNS verification. Do not upload a
   certificate or disable HTTPS.
4. Keep the old WayRaft service **suspended** until the new instance has passed
   every check in section 5 and the custom domain is serving traffic. Only then
   delete the old service. Do not delete it first: it is the fallback while the
   new deployment is being verified.

Apex domains need an ALIAS/ANAME record rather than a CNAME; use a subdomain if
your DNS provider does not support those record types. Region cannot be changed
after creation — if Singapore was the wrong choice, create another service.

## 5. Verify with curl

Set the host once. Use the custom domain after it is verified, or the
`onrender.com` URL for a first smoke test:

```bash
BASE=https://review.example.com
```

### Health and page

```bash
curl -fsS "$BASE/api/health"
# {"ok":true}

curl -sSI "$BASE/" | head -n 5
# HTTP/2 200
# content-type: text/html; charset=utf-8
```

A correct health response is HTTP 200 with `{"ok":true}`. A `502`, `503`, HTML
error page, or connection timeout means the container is not listening on
`$PORT`, the health check path is wrong, or the deploy has not gone live. A
`404` from an `onrender.com` hostname usually means the wrong service name or a
deleted/suspended service.

The page should be the ForgeFlow workbench/login page. A JSON `404` or a
directory listing at `/` means the static UI was not copied into the image.

### Session

```bash
# Unauthenticated access must be rejected.
curl -sS -o /dev/null -w '%{http_code}\n' "$BASE/api/runs"
# 401

# Exchange the invite code for a session cookie.
curl -sS -i -c /tmp/forgeflow-cookie \
  -X POST "$BASE/api/auth/session" \
  -H 'Content-Type: application/json' \
  -d '{"invite_code":"<your-invite-code>"}'
```

A correct response is `201` with a body like
`{"uid":"...","expires_at":"..."}` and a `Set-Cookie` header for `ff_session`
containing `HttpOnly`, `SameSite=Lax`, and `Secure`. A `401` with
`{"detail":"invalid invite code"}` means the code does not match the deployed
`FORGEFLOW_INVITE_CODES` (check for stray spaces or a stale value). A `422`
means the JSON body is malformed. If the cookie is present but lacks `Secure`,
`FORGEFLOW_SECURE_COOKIE` is not `true`.

### Runs and a run detail

```bash
curl -sS -b /tmp/forgeflow-cookie "$BASE/api/runs"
```

The correct result is a JSON array of four records:

- `permission-split-pi-20261021-09` — scenario A, score 100
- `permission-split-pi-b-20261021-01` — scenario B, score 100
- `p5-B-nop-meta-r1` — B no-op control, score 0
- `p5-heldout-2281-pi-r1` — held-out task, score 0

An empty array means the image has no `/app/demo-runs`: check that
`demo-runs/` was committed before the build and that the Dockerfile copied it.
A `401` means the cookie jar is missing or the session expired.

```bash
curl -sS -b /tmp/forgeflow-cookie \
  "$BASE/api/runs/permission-split-pi-20261021-09"
```

The detail should report `"score": 100.0`, `"strict_success": true`,
`"attestation": {"status": "verified", ...}`, and a recovery section with an
executed plan. `p5-B-nop-meta-r1` and `p5-heldout-2281-pi-r1` have no recovery
plan and score `0.0`; that is expected, not a deployment failure. A `404` means
that run id is not in the hosted subset.

### Knowledge answer

```bash
curl -sS -b /tmp/forgeflow-cookie \
  -X POST "$BASE/api/knowledge/answer" \
  -H 'Content-Type: application/json' \
  -d '{"question":"审批 policy_sha256","limit":3}'
```

A correct response has `"found": true` and citations such as
`docs/P2_产品API.md:49-49`. `"found": false` with no citations means the
knowledge corpus is missing from `/app`; verify `FORGEFLOW_KNOWLEDGE_ROOT=/app`
and that the image copied `README.md`, `docs/`, and `contracts/`.

### Optional write-protection checks

```bash
curl -sS -b /tmp/forgeflow-cookie "$BASE/api/config"
# {"deployment":"review","runner_enabled":false}

curl -sS -b /tmp/forgeflow-cookie \
  -X POST "$BASE/api/runs" \
  -H 'Content-Type: application/json' \
  -d '{"scenario":"A","idempotency_key":"review-key-0001"}'
# {"detail":"runner_disabled"} with HTTP 503
```

If `/api/config` reports `local` or `runner_enabled: true`, the environment
variables were not applied; fix them before sharing the URL.

## 6. After verification

- Confirm the custom domain has a valid certificate and `https://` redirects
  work; test in a private browser window.
- Keep the old WayRaft service suspended during the whole verification window.
- Once the new service is stable, delete the old WayRaft service. This is a
  deletion of the old service only — it does not touch `forgeflow`.
- `autoDeployTrigger: 'off'` means new commits do not deploy automatically.
  After changing `demo-runs/` or the code, run **Manual Deploy → Deploy latest
  commit** and re-check `/api/health` and `/api/runs`.
- Rotate the invite code by updating `FORGEFLOW_INVITE_CODES` in the Render
  environment and restarting the service. Rotating `FORGEFLOW_SESSION_SECRET`
  invalidates every existing session.
