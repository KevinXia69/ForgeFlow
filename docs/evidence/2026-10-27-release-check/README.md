## 本轮真实问答

[live-qa.json](live-qa.json) 保存最终公开 API 答复与回合检查，[provenance.json](provenance.json) 保存后端文件哈希、模型配置及派生数据说明。

| 输入 | 观察到的结果 |
| --- | --- |
| 历史成功案例的数量及保留安排 | Nebius 托管的 `nvidia/Nemotron-3.5-Super-VL` 经 DSH CLI 回答，17.099 秒，最终来源为 `model`；取消及替代各 3 件，保留 4 张制造单合计 40 件和 5 张组件采购单 |
| 明确标注的 7/8 失败变体 | 同一路径真实问答，5.848 秒，最终来源为 `deterministic`，原因为 `model_evidence_mismatch`；答复明确原始验收失败，并列出通过 7 项、适用 8 项 |
| 先停止再发送同一回合 | 停止返回 200；该 ID 的启动与恢复均返回 409，不生成新回答 |
| 完成回合恢复 | 返回 200，最终正文及来源与原回合一致，耗时 0.006 秒 |

两条问答都使用隔离的本地案例存储，案例文件在请求前后字节不变。成功案例的 ERP 记录来自历史执行；失败案例是明确派生的测试数据。失败答复中的“执行状态成功”描述保留的单据执行记录，与其后明确给出的“原始验收失败”是不同字段，不代表整体任务通过。

这两条是应用层问答请求数，不是供应商底层请求次数或计费用量。仅归档最终公开答复，没有提取原始模型正文或隐藏推理，不能据此判断模型原文正确率。DSH 问答也不代替 Pi 压缩用量的真实运行验收。
