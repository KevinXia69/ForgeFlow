# 准备、批准、执行、回读、验收与交付

## 各阶段分别说明什么

准备表示系统已生成可审阅方案。用户批准的是页面展示的具体方案版本，
选择候选方案不等于批准。批准记录必须与对应计划、快照和权限绑定。
只有获得有效批准的执行器才可应用业务变更；聊天不能替代这个授权。

执行记录说明已派发或已记录的动作。单据变更条目数不等于底层 ERP 事务次数。
执行结果未知时可能已经发生部分写入，不能根据缺少回执推断零写入，
也不能自动重试批准或重新执行。

回读表示重新读取系统中的业务记录，核对字段和状态是否符合已批准的变更。
原始验收表示任务原始检查器对适用业务规则进行判断。两者需要分别报告，
只看总分或“成功”字样不能替代对验收来源与严格通过状态的检查。

## 51/51 能证明什么

在对应历史受控案例中，51/51 表示 51 项适用任务规则通过。
它不能外推成全部场景的成功率、法律合规证明、第三方认证或生产可用性承诺。
其他案例应显示自己的规则数量、得分及验收状态，不能照搬 51/51。

## 能否说明客户已经收到货

不能。计划按期可行、ERP 单据变更、实际生产完工、发货和客户签收属于不同事实。
原始任务验收和 ERP 回读均不证明物理交付。没有独立出货或签收记录时，
应明确当前案例未提供这类交付证据。
