## 二 工作包 A 利润率计算与兼容

### 统一计算定义

新增支出覆盖收入，只统计由成品采购或制造覆盖的销售数量；现有成品库存覆盖的销售收入不进入这个分母。费用继续采用整份计划的采购与制造费用，包含保留的单据，不改成新建单据金额或相对旧计划的费用增量。

```text
新增支出覆盖收入 = Σ（每张销售订单的采购覆盖数量 + 制造覆盖数量）× 对应销售单价
计划费用 = 成品采购费用 + 零部件采购费用 + 制造标准费用
新增支出利润率 = 1 − 计划费用 ÷ 新增支出覆盖收入
有效门槛 = max（原题门槛，用户追加门槛）
允许计划费用上限 = 新增支出覆盖收入 ×（1 − 有效门槛）
费用余量 = 允许计划费用上限 − 计划费用
```

客户预算继续按完整销售订单金额检查，与新增支出覆盖收入分开。所有合规判断先用精确金额计算，再格式化展示；不得用四舍五入后的百分比决定通过。金额精度与求解器的分币模型对齐，显式检查精度差异，不通过新增宽松容差掩盖不一致。

独立检查必须从已验证的成品分配关系与销售行重算分母，不能直接相信求解器输出的 `new_spend_margin`。可共用公式与数值处理函数，但检查端仍须独立验证数量、价格、成本与绑定关系。

边界规则如下，作为本次实现约定：

| 情况 | 合规处理 | 展示 |
| --- | --- | --- |
| 覆盖收入大于零，费用为零 | 按公式判断，利润率为 100% | 展示 100%，不依赖上游可能为空的派生字段 |
| 覆盖收入与费用均为零 | 新增支出不等式成立，其他业务约束照常检查 | 利润率不适用，不伪造 100% |
| 覆盖收入为零，费用大于零 | 拒绝 | 说明分母与费用不匹配 |
| 价格、分配或成本证据缺失 | 不生成可批准的合规结论 | 未知或明确错误，不按零处理 |

### 指标版本和旧方案处理

为新指标增加明确的计算口径标识及必要的 schema 版本。新版本至少能核验：采购／制造覆盖数量及收入、现货覆盖数量、计划费用、原始和有效门槛、计算口径、关联计划与事实快照。复用现有成本和分配证据绑定，不建立第二套无法相互核验的数据。

口径版本必须进入可执行计划的版本或 manifest 约束，修改口径后生成新的 `plan_id`。旧版指标可作为历史数据读取，不能被新代码静默解释为已经修正的合规指标。

| 旧记录状态 | 升级处理 |
| --- | --- |
| 已完成 | 原始计划、批准、哈希和验收回执保持原样；需要解释时附加独立的口径更正说明 |
| 尚未开始执行 | 标记需要重新准备；获取新快照、求解并生成新版本后重新审批；服务端拒绝旧批准继续执行 |
| 执行中、部分执行、结果未知 | 保留原 journal、计划和来源绑定，先回读与恢复；不得直接生成新计划并重放 |

升级前盘点未完成任务。存在未完成执行时，保留对应来源版本的恢复能力，或先完成恢复再切换；旧版本恢复入口不得继续接收新任务。回读与对账可以沿原记录进行；继续执行剩余写操作前，必须对原计划追加新口径独立复核，并形成绑定该复核记录和剩余动作的恢复授权，不能自动沿用旧口径批准。复核失败则停止剩余写操作，进入受控处理；原计划、journal 和哈希保持不变，新复核作为追加记录保存。

回滚不能把不兼容的新记录交给旧代码，也不能重新开放已知旧口径方案的执行。无法安全恢复时进入只读状态并明确显示需要处理的任务。

## 三 工作包 B 候选目标与原始验收

保留三种选择，默认仍为保留数量。候选区改为说明“使用相同业务事实、硬约束和成本口径，采用不同优化优先级”。用户在选择与审批时应看到以下含义：

| 选择 | 实际优先级 | 必须说明的权衡 |
| --- | --- | --- |
| 尽量保留既有数量 | 先最小化既有采购／制造路径的数量偏移，再降低费用 | 在给定数量规划下优化旧制造安排，不能保证所有 ERP 改动最少 |
| 优先降低规划成本 | 优先降低模型中的采购与制造费用 | 可能取消仍可保留的安排，改变原题保留优先级 |
| 优先保留制造产能 | 优先减少标准制造工时 | 可能增加采购费用、减少旧安排保留量；不是实际工时或交付提前量 |

复用现有 `product_objective`、候选配置版本、manifest、计划 ID 和审批记录。目标必须在候选、所选方案、审批摘要及回执中一致；重新生成方案或改变所选计划后，旧批准不得复用。本轮不以另建政策版本系统为前置条件。

业务约束检查与原始任务验收分开呈现。原始验收继续按 `repair_plan` 评分，不改规则、参考结果或通过标准来适配其他偏好。默认路径应维持原题规则与最优性；成本／产能候选即使满足业务约束，也可能降低原题得分。如果运行原始验收，应展示其真实结果，不将自定义目标的成功冒充原题满分。

验收要求：固化“保留数量／成本／产能”三种合成方案，分别保留旧制造数量 `6 / 0 / 0`、费用 `62 / 50 / 90`，且全部排除故障工位。验证默认目标不变、伪装目标被拒绝、不同候选的批准不能串用；中英文说明与实际求解目标一致。

## 四 工作包 C 影响范围与文档

### 页面和问答

优先从现有影响关系与事实快照推导范围，不能继续用总订单数和总件数代替直接影响，也不能把以下案例数字硬编码为通用逻辑。关系或数量证据不足时显示未知。

| 场景 | 全案规划范围 | 直接关联订单需求 | 已识别失效供给 |
| --- | --- | --- | --- |
| A 供应商取消 | 5 张订单，50 件 | Alpine Theater，13 件 | 一笔 3 件成品采购 |
| B 产线停机 | 12 张订单，228 件 | 六张订单，共 112 件 | 三张制造单，53 + 37 + 2 = 92 件 |

A 的交期统一为 8 至 10 天，Alpine Theater 为 10 天。直接关联范围不能被解读成其他订单绝无间接影响。

建议用于 A 的简介：“案例覆盖 5 张订单、50 件需求，交期为 8 至 10 天；一笔 3 件成品采购失效，需要修复相关订单的供给。”

执行回执分别展示业务单据动作和已确认执行步骤。历史 A 可表述为“两项采购动作，7 个回读确认步骤”；7 个步骤不推断为 7 次数据库写入，保留制造数量也不等于其相关工序记录完全未写入。新运行的数字须来自新回执，不固定为 2 和 7。

### 文档和演示材料

更新 README、当前评委指南、中英文架构与能力说明。为 `CAPABILITY_MATRIX_EN.md` 等历史文档增加醒目的历史状态及当前指南入口；检查 README 的链接，避免继续将过期文档当作当前能力总览。

能力边界统一为：当前完整执行支持一个成品和一层 BoM；只读规划输入能采集更深层物料关系。`planning-metadata-v1` 提高已有工时、成本和提前期的可见性，不将其宣传为未经增强的相同输入条件。区分自主研究运行、人工审批产品流程、只读演示和真实沙箱执行。

先修数据和页面，再核对截图中的利润率、成本余量、影响数量、交期、动作及步骤计数。PPT 和录屏更新已按用户后续指令取消。历史验收原始 JSON 和原始录屏作为历史材料保留，不覆盖为新版本结果。

验收要求：中英文同一问题给出同一业务事实；有计划、无计划、缺少影响关系三种状态均不把案例总规模误称为直接受影响范围；公开页与工作台相关字段和说明一致；当前指南与部署能力入口不再互相矛盾。

## 五 工作包 D 回归与发布证据

### 验证顺序

1. 先运行新增反例和受影响后端测试，确认公式、独立检查、版本兼容和审批约束。
2. 验证 API、候选列表、检查卡、问答、回执和公共页面使用同一指标版本与含义。
3. 按仓库发布要求运行完整后端测试、两套前端的类型检查／构建／smoke，以及页面一致性和字体检查。
4. 在隔离沙箱完成“读取事实 → 准备 → 选择 → 人工审批 → 执行 → 回读 → 原始验收”。
5. 完成旧记录升级、部分执行恢复和回滚演练，再形成可审阅的发布包与部署步骤。

常规命令沿用仓库脚本，并在实施时核对实际版本与运行前提：`uv run pytest -q`；分别在 `web` 与 `web-public` 运行 `npm run typecheck`、`npm run build`、`npm run smoke`；运行 `scripts/check_web_parity.py`、`scripts/check_typography.py` 和 `scripts/first_look_audit.sh`。本方案的新增内容是上述业务反例、兼容场景与验收判据，不以重复运行数量代替验证。

发布前必须完成 P0 和 P1。利润率错误、旧批准仍可执行、未完成任务无法恢复、默认路径原始验收退化，任一项未解决都阻塞发布。P2 实验不阻塞本轮修复发布。

## 六 工作包 E 保留数量改进实验

该实验已作为默认关闭的独立功能实现并验证，仅用于当前支持的一个成品和一层 BoM；是否启用由可信运维配置决定。目标是在保持原题修复目标和费用不变时，提高可保留的旧制造数量。

先运行现有默认求解器，保存已证明最优的修复值与对应最小费用。随后固定这两个值，允许库存、订单供给和交期分桶共同调整，将旧制造单可复用数量纳入下一层目标。最小实验还可固定每份报价采购总量、每个工位制造总量，仅调整分配，明确优化范围。

只有前两阶段最优性已证明，才把实验描述为固定最优值后的改进。若主阶段只得到可行解，保留原求解状态，不宣称全局最优。实验阶段设置有限时间预算并记录；超时、未能证明结果或独立校验失败时，退回原先已验证方案，标记改进未完成。优化策略与新方案重新绑定，重新审批。

验收反例：早订单 4 件、晚订单 6 件、现货 2 件；有效旧制造单 6 件只能赶上晚订单。原方案保留 4 件、新建 4 件；改进后应保留 6 件、新建 2 件，修复指标仍为 6、费用仍为 56。原有故障排除、产能、材料到货、交期、库存和利润率约束全部满足。

验收同时覆盖无可改进方案、超时、检查失败和旧批准重放。对外仅承诺“在固定主目标、成本和已支持模型范围内优化旧制造数量”，不声称全局最少单据变更或 ERP 写入。
